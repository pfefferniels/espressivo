# Comparison fixtures — provenance, licence, and byte-faithfulness policy

These eleven files are **vendored third-party material**, not generated by this project. They
are the complete XML half of the MPM format's own sample-encoding corpus, and they exist here
because they are the only real multi-performance MPM documents available to the comparison
campaign: no fixture under `tests/integration/fixtures/**` has more than one `<performance>`
(all 33 have exactly one), so nothing already in the repo can exercise a comparison at all.

## Byte-faithfulness policy

**The file contents are byte-for-byte identical to the source. Only the file names differ.**

- Contents are unmodified, verified with `cmp` against the source at copy time; the SHA-256 of
  every file is recorded below so any later drift is detectable.
- **The UTF-8 BOM is deliberately preserved** on the three files that carry one. It is not an
  accident to be cleaned up: it is the exact byte pattern that made these documents unparseable
  before `4211f58` (PARITY.md §1, `CMP1`), so keeping it makes these fixtures a regression pin
  for BOM tolerance against real data rather than a synthetic string.
- Single-quoted attributes, whitespace, element order and `xml:id` presence are likewise left
  exactly as authored.
- **Do not reformat, re-serialize, prettify or "fix" these files.** If a future need arises to
  compare against a normalized form, normalize in the test, not on disk.
- Names were changed to lowercase-hyphenated ASCII because the originals contain spaces, commas
  and mixed case, which are awkward for shell tooling and path handling. The mapping to source
  paths is in the inventory below; nothing else about the files changed.

### What each one is for

- **`telemann-grave`** — the primary comparison fixture. Three named interpretations of one
  piece in one document, contrasting exactly as the campaign's use case describes; the richest
  of the set (tempo 21, dynamics 60, articulation 171, rubato 39, asynchrony 4,
  accentuationPattern 33, style 19, summed over the three). Carries a BOM. Measured tempo
  distances during W0 were musically sensible: Baroque↔Romantic 0.108, Fast ≈1.0 from both.
- **`vulpius-die-helle-sonn`** — the second three-performance document, and the one that varies
  `ppq` (480). Both it and its `.msm` carry a BOM.
- **`albert-du-mein-einzig-licht`** — two performances, one of them ("Like a robot")
  deliberately mechanical, so it is the natural fixture for asserting that a distance is *large*
  between an expressive and a deadpan reading. No BOM, so it controls for the BOM variable.
- **`bach-bwv1007-minuet2`** — single performance, but the densest articulation writing in the
  corpus (204 `<articulation>`) and `ppq` 480 with a BOM. Useful as a one-sided input and for
  cross-`ppq` normalization tests.
- **`aller-augen`** — single performance, small, and the only file here with substantial
  `xml:id` coverage (60), so it is the fixture for anything that wants stable element identity.
- **`minimal.mpm`** — 589 bytes, one performance, no maps at all. The degenerate case: a
  comparison of it against itself, or against anything else, must not throw.

## What was deliberately not copied

The source folders also hold `.mp3` renderings, `.pdf` and `.png` scores, `.mid` files, one
`.mei`, and MPM-Toolbox `.mpr` project files. None is needed to compare performances, and the
audio and score images are large; leaving them out keeps this tree at ~308 KB. They remain
available at the source path recorded above should a future item want them.

## Relationship to `tests/integration/fixtures/**`

Separate tree, separate rules. `tests/integration/fixtures/**` is immutable Java-generated
ground truth governed by charter invariant #2, and nothing here is added to it. This tree is
third-party input data for the comparison module: also not to be edited, but for a different
reason — provenance rather than parity.
